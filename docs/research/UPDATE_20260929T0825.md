## CPU camera pilot

PyCOLMAP 4.2.0 was installed as an isolated target beside the existing Python
runtime. No existing interpreter package was replaced; no Torch, dense model or
GPU computation was required. This adds a sparse-estimation option, not a Pi3X
implementation. See the [fixed initial protocol](SFM_INIT_PROTOCOL_20260929.json).

```bash
python tools/freeze_video_frames.py --source-receipt /remote/source-receipt.json --output /new/frames
PYTHONPATH=/remote/runtime_addons/pycolmap_4_2_0 python tools/initialize_video_cameras.py \
  --frames /new/frames/freeze.json --protocol docs/research/SFM_SEEDED_CONTROL_20260929.json --output /new/cameras
```

Use the existing numerical Python environment and the isolated pinned PyCOLMAP
target. Incomplete initialization writes a receipt and returns a nonzero CLI exit.

All trials use the same three scenes and eighteen frames, SIMPLE_PINHOLE shared
intrinsics per scene and one connected model. Readiness requires all six frames
registered and at least 100 triangulated points. The installed pipeline's built-in
initialization search/constraint relaxation is part of its fixed algorithm; its
logs are retained. No evaluation gate was relaxed after looking at results.

The cap increase did not change actual extracted keypoint counts: all images
were below the cap; [the database audit](evidence/heartbeat_0825/feature_count_audit.json)
also found identical keypoint-data hashes. Differences in that initial pair cannot be attributed to a
changed feature set; two-view RANSAC had still used the library default seed -1.
The subsequent pair explicitly set that seed in both arms before changing only
the detector peak threshold. Keypoint counts increased, but full registration
did not. Point counts still vary between repeated control runs, so a fixed seed
is not advertised as bitwise reproducibility or a statistical comparison.
