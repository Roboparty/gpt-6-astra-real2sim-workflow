## Frozen comparison and retained legacy failures

The [export protocol](INTERCHANGE_PROTOCOL_20260929.json) fixes two already
validated inputs from `unified_validation_001`: an empty room with one fixed
luminaire, and a room containing one translated/rotated furniture assembly.
Source model/scene hashes and all six format checks were fixed. No geometry,
material, camera or threshold was fitted to the outcomes.

The shared exporter ran at its existing full settings on CPU with two threads.
The old reload checker passed Blender/GLB but reported missing source cameras in
both USD files. Those **4/6 legacy passes and 2/6 failures remain retained**. USD
import names the actual camera `Camera`; the old checker only looked for the
original object name and lacked a usable frame-ID fallback in these fixtures.
This was an identity-resolution failure, not evidence that a camera was absent.

The [strict evaluator specification](STRICT_INTERCHANGE_EVALUATOR_20260929.json)
was fixed before strict evaluation. Its reference comes from the original model,
not the exported `.blend`. It independently loads each file and checks:

- Canonical evaluated world AABBs within the unchanged 2 mm tolerance.
- Every required part is visible geometry with the right owner; an Empty with
  the same name cannot substitute for a missing part.
- No unowned render-visible geometry, and a real, unambiguously identified
  `CAMERA`. Identity may use explicit object/data names, frame ID or named parent
  identity; no geometric proximity search is used.
- Source camera world matrix within 1e-4, and normalized view-frame projection
  within 1e-5 at the original JSON raster and pixel aspect.
- Original input and exported-file hashes remain unchanged during inspection.

## Actual native integration and negative controls

The core evaluator is now `workflow/r2s/interchange.py`; its bytes are identical
to the tool implementation that ran the strict comparison. The small tool entry
remains compatible. Frozen remote code snapshots preserve the original executed
paths and hashes.

For cases with `generation_skills`, `stage_worker` runs strict reload immediately
after the shared export. Failed reload prevents a completion response. The later
validate stage requires the bound report, all three passing format rows, and
matching `.blend`/GLB/USD bytes. Export and reload logs have separate names.

Five real Blender in-memory controls passed: unchanged source, same-name Empty
instead of a camera, unowned extra mesh, a required part replaced with an Empty
while alternate geometry preserves its owner/AABB, and changed field of view.
All four mutations were rejected. [Control results](evidence/heartbeat_1346/negative_controls.json).

Six native stage tests also passed: valid export and validation, corrupted GLB,
missing report, changed file bytes, and empty format records. These tests replay
the already generated real export files instead of repeating the expensive
export command; strict Blender reload and actual MuJoCo validation run normally.
They use synthetic stage packets and do not represent full Agent acceptance.
