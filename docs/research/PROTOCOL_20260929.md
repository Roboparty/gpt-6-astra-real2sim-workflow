## Questions and independent comparisons

1. Does a structural shell collider eliminate the observed 25 mm error while
   preserving the visual scene, transforms, wall thickness and declared openings?
   Compare old and new exporters on identical retained export inputs. Fixed
   enclosure tolerance: 6 mm. Openings must be tested as openings as well.
2. Does fixed-camera, per-object geometric feedback expose missing objects,
   silhouette errors and landmark errors without dropping failed observations?
   Validate the instrument with known perturbations before an agent A/B. The agent
   A/B must use identical source observations, initial geometry, model settings,
   evaluation set and budget. No measured agent uplift until both arms run.
3. Are material and contact assumptions sourced, dimensionally valid and actually
   applied to the engine? Baseline friction stays unchanged unless a candidate
   explicitly requests a preset. Validate compiled contact values, not JSON alone.
4. Do optional hinges/cloth/soft bodies remain absent by default, and when enabled
   create the requested numerical degrees of freedom without changing the static
   reference? Report dynamics separately from reconstruction accuracy.
5. Can a task evaluator reject incomplete release, containment, withdrawal,
   closure or sustained-stability events? Initially use explicit synthetic traces;
   they validate the evaluator, not robot task success.

## Budgets and evidence

First development round: at most 8 candidate revisions per mechanism, 2 hours of
CPU wall time per run, and 4 GPU-hours total (only after a live external-work
check). No paid API requests are launched by the repository runner. Current local
agent reasoning is not included in compute accounting; its cost is unknown.
Budget extensions require a versioned protocol amendment before more experiments.
Record every attempted run, failure, timeout and infrastructure error. Do not
resample failed cases, reset budgets, or assemble a per-case best-of leaderboard.
Artifacts include source and code hashes, effective parameters, runtime versions,
elapsed time, return codes and individual verdicts. Missing metrics stay unknown.

## Evaluation and promotion

- Geometry: per-observation pixel errors/mask IoU, coverage, missing observations;
  separately grouped fitting and held-out data. No image score is a 3-D accuracy.
- Collision: room boundary error, declared opening clearance, support and contact.
- Dynamics: actual state trajectory, limits, penetration, warnings and sustained
  stability; assumed physical parameters remain assumed even after a successful run.
- Efficiency: end-to-end wall time, CPU/GPU use and model requests when known.
- Appearance: actual source/candidate overlays and fixed views; independent review
  of textiles, accessories and lighting. Metric gains do not override visible errors.
- Prior-based unseen surfaces are plausible completions, not recovered truth.
- External comparisons: AHa-3D for video-to-room geometry; GPT6-real2sim for
  contact replay; Real2Gym for task verification. Their published numbers are not
  interchangeable with this room's ArtVIP scores.

SOTA requires a preregistered shared benchmark, lawful available source data,
same input regime (single photo vs video reported separately), reproducible
competitor baselines, comparable budgets, repeated independent scenes and seeds,
and uncertainty on the primary metric. Until those runs exist, report capability
improvements and unresolved gaps, not a SOTA achievement.
