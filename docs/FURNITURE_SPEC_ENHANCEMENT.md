# 家具尺寸与精确型号：增强机制和当前证据

本项目强调将图像与可核实的家具规格共同用于建模。这里区分可解释的增强机制、当前代码接口，以及已经做过的实验；不把设计目标当作测量结果。

## 1. 可靠尺寸如何帮助重建

单张照片通常不能唯一决定真实尺度和隐藏深度。与可见部位对应的可靠尺寸，可用于约束尺度、形状或相机拟合，减少任意调整物体比例的自由度。

尺寸必须附带对象、数值、单位、来源及定义。整体外廓宽度、桌板宽度、座面宽度和座高不是同一个量；标称产品尺寸与现场测量也应分别记录。需要先核对透视、支撑平面、遮挡和版本，再决定约束哪些参数。一个已知长度不能自动解决所有相机和形状歧义。

输入尺寸是建模依据；用于独立评价的尺寸应另外留出。不能用已经参与拟合的目录尺寸再宣称独立测量准确度。

## 2. 详细型号如何帮助结构选择

品牌、系列名和“外形相似”不足以确认同款。需要核对精确型号、代次、尺寸变体、配置及能辨认的构造特征。

型号证据可能帮助区分四腿/悬臂、靠背支柱位置、桌架形式和部件关系，降低不合理补全的机会。商品规格图仍可能简化隐藏构造；具体版本不一致时，应降低其权重或排除，而不是强行把照片拟合到错误资产。

## 3. 两条策略

| 策略 | 允许的增强 |
|---|---|
| A：独立建模 | 可查询并使用核实的规格，几何由执行 Agent 独立构建；A 不等于禁止尺寸先验 |
| B：准确同款资产辅助 | 在 A 的基础上，允许采用身份、变体与使用条件已经核实的同款资产，并重新检查几何、单位、朝向和源图一致性 |
| 无法核实 | 对应对象回退 A，记录原因；不以相似库存模型冒充同款 |

B 的身份标志由调用方提供。当前 `branch_b` 是分支接口，不会自行检索厂家、验证许可证内容或完成通用 CAD 导入。执行 Agent 仍须完成真实核验与适配。

## 4. 当前实现状态

| 能力 | 状态与定位 |
|---|---|
| 接收尺寸来源、精确型号和不确定性 | 已有任务模板与识别阶段协议；由 Agent 执行 |
| 尺寸先验进入数值相机拟合 | `workflow/r2s/calibration.py` 中有 `fit_camera` 实现；需调用方提供有效对应与平面约束，当前案例没有调用这条路径 |
| 整件家具姿态和尺寸联合拟合 | 当前案例已执行；`case/fit_furniture.py` 使用固定相机与常见尺寸先验，两把椅子共享形状假设 |
| 拟合结果驱动可编辑部件 | 当前案例已执行；`case/furniture_model.py` 核对观察和参数哈希后构建局部装配 |
| 同款资产辅助 B | 有分支约定和接口；无通用自动检索、完整许可验证及资产导入流水线 |
| 厂家尺寸/精确型号增强的量化效果 | 尚未验证；当前没有对照结果 |

当前实拍中的候选型号均未达到准确同款确认条件，目录记录没有采用厂家尺寸。相机尺度使用层高 2.8 m 的先验，B 全部回退 A。示例图展示的是结构修订效果，**不是尺寸或型号增强的对照实验**。

## 5. 已验证的其他优势

- 观察文件、实际部件和模型版本有可检查的关联。
- 用完整家具与组合视角发现局部连接问题，配合可见网格检查，而非只检查外廓或碰撞代理。
- 几何、材质、照明、数值动力学和格式传递分别给出结果。
- 保留错误注入、实际失败和修订记录，便于复查。

这些结论的范围是已公布案例和回归检查；没有与其他框架进行同条件性能比较。

## 6. 如何补做增强对照

后续应选择拥有真实型号和独立尺寸资料、且获授权的实拍案例，保持相同图像、评价方式与资源预算，分别比较：图像与普通先验；加入已核实尺寸；再加入精确型号；在确有可用同款资产时另测资产辅助。

分别记录原始生成结果、人工修正工作、留出尺寸/视角误差、部件正确性、接触/支撑问题与耗时。尺寸和型号是两个因素，同款资产是第三个因素，不能一起改变后把所有改善归因于其中一个。没有独立真值时只报告拟合与工程结果。

开始任务前使用 [任务模板](../public_contract/REQUEST_TEMPLATE.md) 提供这些资料；目前没有可直接投喂任意家具目录的自动接口。
