# 视觉返工闭环

本次改造把现有 quality_v2 的审核结果接回执行器。模型、材质和灯光仍由具备读图与工具能力的 Agent 制作；执行器维护证据、依赖、版本和停止条件，不代替视觉判断。

## 使用

新执行 `tools/init_case.py` 的案例默认启用；旧案例保留原合同。自定义案例在 case.json 中增加：

```json
"refinement": {"max_revisions": 8, "max_stagnant": 3, "max_seconds": 7200}
```

启用后先完成新的观察合同，不能沿用旧审核冒充新版证据。完整字段和示例见 [refinement.md](../workflow/r2s/prompts/refinement.md)。普通用户无需编写这些 JSON，执行 Agent 负责。

1. 观察阶段声明重点对象、源图裁剪和区别性特征；家具结构观察中出现的对象必须包含在内。
2. 可执行渲染生成 `render_binding.json`，绑定实际场景、模型、源图、渲染条件及图像哈希，并生成对应对象裁图。
3. 几何与最终审核都提交 `appearance_review.json`。原图视角、局部细节和新视角结构分别判断；重点对象逐个检查。失败候选同样必须提供实际证据。
4. `changes_requested` 带上缺陷、证据和 `revision {stage, reason, strategy}`。`run()` 复用 `revise()` 使负责阶段及下游失效，然后继续执行。交互式 Agent 会收到新的 `awaiting_agent` 包；配置 `agent_command` 时继续调用该命令。
5. 后续候选引用最佳审核的哈希，提供修改前后真实图像、相同对比协议和 `better/equivalent/worse` 判断。退化版本不能完成。历史目录和最佳候选的模型引用保留，不自动把旧结果塞进新依赖链。
6. 预算和停滞次数跨续跑保存；两次无改善后要求更换策略，到上限返回 `needs_revision`。计算时间统计执行器工作，不计交互等待。需要更多资源时调整明确的上限；没有自动降低验收标准。

相机/观察返工会归档原比较序列，下一候选重新建立基线，不能把条件变化报成质量提升。材质和灯光可以作为实验变量改变；相机、分辨率和色彩变换需匹配。对单图无法确认的隐藏面仍报告假设。视频需从任务包里的已解码帧显式选定主对比图；不能把视频文件当图片读入。

`freeze()` 现在要求所有配置阶段有效，包括 report 和适用的最终物理审核。局部实验不能冻结成完整交付。

## 避免“位置对了、形状不对”

模板只能作为初始模型。坐垫厚度/鼓起、杆件渐变、靠背曲率和端点如果不在原模板的变量中，Agent 必须改造表达或局部重建。可见模型和碰撞代理继续分离。

对遮挡区域先判定部件归属，再拟合长度。实拍案例中，桌横梁在图像中穿过椅背区域，旧椅背还使用固定 `width/2 + 0.070` 的半跨度。单独拟合椅子的座面、脚点和支柱不会约束椅背端点；因此需要额外比较端点及弧线，保留邻近桌子的几何。这项约束应写入通用观察/复查规则，而不是把某一把椅子的尺寸写成所有场景的默认值。

## 验证与范围

### 表面结构证据与真实网格验收

2026-09-25 鞋柜纠错暴露了另一类缺陷：型号尺寸核对正确、包围盒正确、关键点拟合通过，仍可能把明暗或纹理误建成大量横条。旧的人工局部验收也会误放行。现在 refinement 默认启用 `surface_contract_version: 1`；版本进入阶段指纹，旧缓存不能直接继承新验收。显式的版本 0 仅用于旧协议兼容，不代表通过新表面验收。

观察阶段需交付绑定原图 SHA 的 `surface_observation.json`，覆盖所有重点对象。原图裁切逐像素核对；面板、横档、沟槽等必须分类为几何、颜色、光照或不确定，并明确数量。型号候选还需实际检查并交付厂家结构照片，目录尺寸文字不能替代。没有充分深度证据的线条不得生成凸条、槽或位移。

建模阶段交付 `surface_realization.json`，逐项绑定已接受的观察及真实网格/顶点组。执行阶段从求值后的网格检查特征数量，检测无证据支持的重复细横条；对声明为连续外平面的区域，用实际外侧三角形重叠检查层板端部穿到侧板外表面的情况。修改器造成的数量变化也会被检查。每个区域输出中性正视及侧光近景，临时隔离只用于诊断，不保存进正式场景。

几何审核及最终材质审核均需 `surface_review.json`，绑定当前模型审计和实际图像。逐项检查拓扑/数量、几何与颜色的区别、边框比例及明暗对比；实测失败或任何可见错误均禁止 `complete`。解释错误返回观察阶段，实现错误返回建模阶段，随后重跑受影响的输出。文件格式见 `workflow/r2s/prompts/surfaces.md`。

这些检查不是万能的图像语义判定器。重复细条筛查有启发式限制，连续雕刻的复杂凹槽仍需原图优先的视觉复核；不得把脚本通过当作实物精度证明。

### 局部重建后的几何元数据

`blender_metadata.py` 从当前依赖图的实际求值网格重算语义对象的世界包围盒，包括修改器、曲线和实例变换。`position` 表示世界包围盒中心，`dimensions` 表示世界轴向跨度，包含五金和床品；它们不能直接当作旋转家具的目录宽深。

每次 `build_geometry` / `build_render` 都在新尝试的 JSON 副本中自动同步，并记录修改前的差值，不改写历史模型或旧 JSON。渲染和导出再次独立检查；缺少语义对象网格、非有限顶点或超出 0.01 mm 容差的陈旧记录会阻断。建模脚本也可调用同一函数，在局部重建后立即同步。`tools/test_evaluated_metadata.py` 在真实 Blender 中回归局部顶点修改、修改器、曲线和隐藏对象；不是一次性手工修 JSON。

`python tools/test_refinement.py` 使用明确标注的协议夹具检查返工路由、下游失效、预算停止、最佳候选保护、陈旧图像拒绝和完整冻结门槛。它不是视觉效果评测。

`tools/real_photo_refinement.py` 是实拍局部修改的交互式集成实验入口，运行缩小的观察→模型→渲染→审核图。它复用已有独立重建场景，验证真实模型修改如何进入返工闭环；不导入 V5 资产，也不证明从未见照片独立生成的质量。`tools/rebuild_probe_cushions.py` 和 `tools/shorten_probe_backrails.py` 仅是该案例的修正脚本，不能当作通用家具生成器。

完整模型留在远端。实拍回归的实际结果、小型预览与限制记录在 [验证报告](REFINEMENT_VALIDATION.md)。未经完整新场景实验，不宣称已达到 V5 的通用重建质量。

旧四阶段桌椅回归入口 `tools/real_photo_refinement.py` 显式使用表面合同版本 0，以便复核既有协议证据；它不验证新表面合同。新场景应使用默认版本 1 的完整质量流程，详见 [新版卧室验证](bedroom/README.md)。
