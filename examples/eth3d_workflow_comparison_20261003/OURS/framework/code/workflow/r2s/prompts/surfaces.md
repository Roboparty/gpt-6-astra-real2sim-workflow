# Surface evidence and acceptance (surface_contract_version 1)

A correct silhouette, bounding box, stable simulation or low landmark residual does not validate the furniture front. Read this file when packet.refinement.limits.surface_contract_version is 1 or greater.

Observation: deliver surface_observation.json (schema real2sim.surface-observation/1, source_sha256, regions). Cover every appearance target. Each region has id, entity, pattern, source_box_xyxy, source_crop, allow_repeated_relief, features. The crop must be an unchanged RGB pixel crop of the authorized original. Each feature has a unique id, description and classification: geometry, albedo, lighting or uncertain. Geometry requires count, visible depth_cues and confidence >= 0.75. Uncertain features require alternatives and must not become geometric relief. Count panels, rails, slots and joints explicitly. A weak line is not proof of a groove. Do not inflate confidence to pass a gate.

For a named product candidate, inspect manufacturer photographs, not just dimensions/text. Record product_candidate, manufacturer_image_review (consistent/conflict/unavailable), and manufacturer_images [{artifact,url,sha256}]. Consistent requires delivered image evidence. Manufacturer appearance must agree with the original; conflicting or unavailable evidence leaves identity unconfirmed. Never copy reference evaluation geometry into A.

Model: carry the accepted surface_observation.json and all its crops/manufacturer images unchanged. Deliver surface_realization.json with observation_sha256 and matching regions (id, entity, pattern, inspection_objects, normal_world, up_world, features). Each feature records id, representation and, for geometry, count and mesh_refs [{object,vertex_group?}]. Use separate connected groups for repeated geometric features so the runner measures actual count. Whole continuous surfaces may use whole_surface:true; never use it to collapse repeated panels into one count. Micro bump is for supported albedo detail only and must specify depth_m <= 0.0005. Uncertain lines can be omitted or represented as albedo; never as grooves, slats or displacement.

Executable builds measure evaluated geometry, screen unsupported repeated thin strips, and render each surface in neutral frontal and raking light. This heuristic is not a semantic classifier and does not certify every carved shape. Missing bindings fail the build; a measured mismatch produces a failed audit with images for revision.

Geometry AND final shaded review: deliver surface_review.json bound to the current surface_audit.json via audit_sha256. Cover every region exactly once. Each row has id, evidence (source crop, actual front/raking views), plus topology_and_count, relief_vs_appearance, proportions_and_contrast; each is {status:pass|revise, findings:concrete observation}. First describe/count the original, then compare geometry and shaded contrast. Recheck broad/narrow rail widths and recess depth; a plausible-looking generic cabinet cannot pass. Failed executable audit or any mismatch blocks complete. Return changes_requested to observation if interpretation was wrong, or modelling if implementation contradicted evidence. Preserve rejected attempts and rerun affected materials, renders, evaluation and video after correction.
