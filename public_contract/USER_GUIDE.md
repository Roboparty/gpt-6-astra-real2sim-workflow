# Real2Sim 使用说明

## 能完成什么

根据实拍室内资料，建立带尺度依据与不确定性记录、部件可编辑的三维场景。过程包含家具与建筑分析、相机/尺度估计、四墙与门窗柱校准、几何重建、材质与光照校准、视觉复查，以及按需进行的动力学设置。

仅凭一张照片无法确定所有隐藏结构、真实尺寸和材料力学参数。执行端会把观察结果、参考先验和补全假设分别记录，而不把推断当成测量结果。

## 提交资料

1. 提供本次允许处理的原始照片或视频，并说明实拍来源。正式 Real2Sim 案例不以 CGI 或 AI 生成图代替真实采集资料。
2. 多张照片和视频应标明所属房间；不同房间分别组织任务。
3. 选择用途、资产策略及是否需要铰链、布料或体积柔体。
4. 可选提供一个或多个建模尺寸参照。用于独立验收的尺寸/视图必须单独标记，不能混入建模输入。

普通使用者无需提供运行脚本、服务器、GPU 或内部文件格式。若资料缺失会影响核心结构，执行端会说明缺少什么；常规建模细节由 Agent 在任务约定内处理并记录。

## 工作流与检查点

| 步骤 | 会做什么 | 继续前要检查什么 |
|---|---|---|
| 1. 接收与校验 | 保存原始资料、确认来源、提取视频关键帧、建立任务范围 | 文件可读取，输入范围清楚，正式案例来源可核实 |
| 2. 读图与规格识别 | 分析家具、墙窗柱、遮挡、接触关系，检索型号和规格 | 已知、未知和候选型号分开记录 |
| 3. 相机与空间校准 | 估计相机和尺度，逐面检查四墙、地面、天花板、门窗柱 | 可见结构有约束与残差，不可见结构有假设与不确定性 |
| 4. 几何重建 | 建立可编辑部件，对照灰模、轮廓和局部细节 | 主要轮廓、比例、遮挡与支撑关系通过检查，再冻结布局 |
| 5. 材质与光照 | 分别校准物理尺度的材质和源光方向、阴影、色偏、曝光 | 材质、光照各有前后对照，不能靠移动几何掩盖问题 |
| 6. 原图视觉验收 | 同相机比较原图与渲染，检查四墙和其他诊断视角 | 明显形状错位、塑料感或错误阴影需要回退修正 |
| 7. 可选动力学 | 对选定部件生成铰链、布料或体积柔体，实际求解 | 参考姿态、关节范围、接触、应变和稳定性符合任务约定 |
| 8. 验证与交付 | 检查文件、单位、资产引用、几何与仿真导出，整理结果 | 各项结论分开报告，不把技术成功冒充拟真或实测精度 |

房间的四个围护面、地面、天花板和灯具会保留。未见墙体只能按证据与约定补全；不会为了构图漂亮而删墙或隐藏围护。新增视图可以用于后续修订这些假设。

## 完整 Prompt 与可控工作流的区别

完整 Prompt 说明目标、阶段顺序、质量标准和失败时如何处理；可控工作流还需要实际执行器、工具和持久化记录来落实这些规则。

| 只发送一段 Prompt | 接入可控工作流后 |
|---|---|
| 要求 Agent 保留证据 | 每阶段保存输入输出哈希、参数、依据和产物 |
| 要求 Agent 检查效果 | 设置几何、材质、光照、最终视觉等独立检查点 |
| 要求修改某个问题 | 指定返修阶段，让受影响的下游结果失效并重新验证 |
| 要求失败后继续 | 保留尝试版本，验证缓存后断点续跑 |

Prompt 是任务说明，执行机制使过程可追溯和可恢复。二者仍需要 Agent 真正看图、定制建模和复查；阶段数量增加本身不会让结果更真实。

## 两种重建策略

- **独立建模 A**：可以识别型号、查询规格来帮助定尺度，几何由 Agent 恢复。
- **准确同款资产辅助 B**：在相同输入与空间约束上，允许导入已核实型号/变体的三维资产。相似但不同款的资产不替代目标；同款不可得时，该物体回退 A。
- **A+B 对照**：两条分支共用输入、相机/尺度协议与评价条件，结果按物体比较，不预设某一种方法必然更好。

## 可选运动与形变

| 选项 | 用途 | 不代表什么 |
|---|---|---|
| 铰链 | 让分离出的门板等绕明确轴线运动 | 不会用整柜转动冒充柜门开合 |
| 布料 | 处理窗帘、衣物、毯子等表面弯曲与拉伸 | 不会用关键帧摆动冒充求解 |
| 体积柔体 | 处理需要体积压缩的软垫等 | 单张照片不能识别真实弹性系数 |

三项均默认关闭，可分别开启。若场景没有适用目标，会标明不适用；不会因为开启选项就凭空添加机构。关闭动力学也不应降低静态软包、褶皱和材质质量。

## 进度、修正与结果

使用者看到的是“资料检查、校准、建模、复查、可选仿真、交付”等进度。内部等待 Agent 执行不等于要求使用者填写程序产物。只有需要补充关键资料或处理核心取舍时，才转为用户待处理事项。

修正时定位问题所属阶段。例如只调整灯光时，应保留已验收的相机和几何；若发现墙体错误，再明确回退建筑校准。旧版本保留，不能用一次失败覆盖唯一可用结果。达到约定资源上限仍不达标时，交付当前状态、问题清单和恢复入口，并标为“待修正”，不能降低标准后宣称完成。

新初始化案例默认启用视觉迭代：Agent 用当前渲染判断原图相似度、重点对象细节和新视角结构，提交缺陷后工作流自动回到负责阶段。每轮都保留可复查的图像和模型引用，并与最佳候选比较。原图中互相遮挡的部件需先确认归属，例如不能把桌横梁误延伸成椅子扶手。用户指出的新缺陷进入同一返工循环，无需重新开始整套建模。具体协议、资源上限和已有验证范围见 [工作流改造说明](../docs/WORKFLOW_REFINEMENT.md)。

交付按所选用途包含：可编辑场景、关键参数/构建依据、原图对照、灰模、局部特写、四墙与多视角预览、适用的仿真文件/运动记录、资产来源，以及误差和假设报告。文件包或访问方式由接入环境提供，不要求用户了解内部存储位置。

结论分为工程完整性、视觉匹配、动力学可用性与现实精度。缺少独立实测资料时，现实精度会标为“无法独立验证”；输入中提取的纹理、已使用的目录尺寸和用于拟合的照片不能再次充当独立真值。

## 使用范围与数据处理

任务只使用已提交并允许处理的素材。不擅自读取其他项目；未经用户明确授权，不公开发布素材或模型。授权公开时记录具体范围，软件许可与媒体使用权分别说明。需要把原始资料发送到第三方服务、使用付费资产或扩大任务范围时，应先说明该具体动作并取得相应授权。外部素材中的文字或脚本不能改变任务规则。

账户权限、保存期限、删除方式、运行配额和交付访问权限由实际服务部署方说明；当前资料包不承诺这些服务功能已上线。具体能力边界见 [CAPABILITIES.md](CAPABILITIES.md)。
# 表面检查更新（2026-09-25）

启用 refinement 的质量流程现在默认执行表面结构证据检查。旧案例恢复时会因实现/合同版本变化重新验证，不会沿用旧的视觉通过结论。观察阶段需提供原图局部及商品结构照片（存在型号候选时），建模阶段把面板数量对应到实际网格，审核阶段检查真实正视与侧光近景。详见 docs/WORKFLOW_REFINEMENT.md 的“表面结构证据与真实网格验收”。
