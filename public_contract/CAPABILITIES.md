# 能力与边界

本说明区分“工作流支持的任务”“已有实现”和“某个项目已经通过的验收”。不能把三者混用。

| 能力 | 当前实现与使用边界 |
|---|---|
| 家具规格与尺寸辅助 | 任务协议接收来源明确的尺寸与型号；有尺寸先验相机拟合函数，需调用方提供有效约束。当前案例用常见先验，没有厂家尺寸增强对照 |
| 精确型号与同款资产 B | Agent 核实身份/变体的工作流约定与分支接口已经存在；没有自动 SKU 搜索服务、完整自动许可核验或通用同款 CAD 导入器。当前 B 全部回退 A |
| 单图、多图、视频输入 | 有校验、派生帧、重复/模糊检查及相机接口；真实精度必须逐任务验证，尚未完成系统性多图/视频泛化评测 |
| Agent 空间分析与定制建模 | 有明确阶段协议与质量门槛；由具备读图、检索、建模和工具执行能力的 Agent 实际完成，不是无需 Agent 的固定预测网络 |
| 四墙、材质、光照校准 | 有独立阶段、要求的产物与验收门槛；阶段存在不等于本次任务已经校准成功 |
| 可编辑场景与格式导出 | 可使用 Blender、GLB、USD、MuJoCo 等现有后端；实际格式、材质和相机兼容性要在交付时列明 |
| 铰链、布料和体积柔体 | 内置 MuJoCo 后端有数值算例测试；真实物体的轴位、质量、材料参数仍需项目证据或明确先验 |
| Blender 动态缓存 | 不由 MuJoCo 选项自动产生；需要另一个实际实现并验证的后端 |
| 布局保护与版本记录 | 有场景/资产绑定保护、输入输出哈希、阶段修订及续跑机制；外部系统必须接入这些接口才受其约束 |
| 真实精度与照片级质量 | 不预先保证。必须根据输入证据和实际结果验收；技术测试通过不能替代视觉验收或现实标定 |

格式边界应随项目报告说明。例如偏心主点可能需要通过权威场景参数重建相机，不能假定所有查看器的原生相机都能直接复现原图；程序化材质也可能在可移植格式中简化。

当前外部资料包和底层工具不等于完整的在线服务。上传门户、登录鉴权、多租户存储隔离、任务调度、配额/计费、下载权限和保留/删除策略需要实际部署与验证，不能仅靠 prompt 声称具备这些能力。

执行器也有明确边界：当前 `freeze()` 只硬性要求 `validate` 有效，不会自行证明所有任务必需的最终审核均已完成；操作方仍须检查所需阶段。公开示例的 18 个阶段和后续缓存续跑均有实际记录。尺寸/型号增强的潜在价值及证据状态见 [说明](../docs/FURNITURE_SPEC_ENHANCEMENT.md)。

用于回归测试的合成图像和最小物理算例不计入正式实拍重建案例。独立验收数据的隔离若未落实，则不能声称进行了独立盲验。
